모든 작업

Python · PostgreSQL · pgvector · RAG

지식 파이프라인

흩어진 메모와 자료를 LLM으로 잘게 나누고, 임베딩으로 연결·군집화해 글로 엮는 시스템. 근거 점수가 낮은 결과는 표시. 블로그 HW Insight의 글을 만듦

배경

메모, 채팅, 웹 자료, 음성 메모처럼 여러 곳에 흩어진 기록을 모아 근거 있는 글로 바꾸는 시스템입니다.

문제

LLM에게 자료를 주고 글을 쓰게 하면 그럴듯하지만 근거 없는 문장이 섞입니다. 자료가 크면 아예 처리되지 않고 넘어가기도 했습니다.

만든 것

  • 텔레그램·슬랙·웹·RSS·이메일·음성(STT)에서 자료를 모으고, 원본은 암호화해 보관합니다. 같은 원본은 한 번만 적재합니다.
  • LLM이 자료를 최소 의미 단위로 쪼개고 보강합니다. 각 단위의 임베딩을 pgvector에 저장하고, 유사도로 관련 단위를 연결해 묶습니다.
  • 묶음마다 핵심 주장(통찰)을 뽑아 원문 근거 점수를 매기고, 점수가 낮으면 표시합니다. 자동으로 쓰는 글은 이 통찰에서 출발합니다.
  • 검색 기반 합성(RAG)도 있습니다. 검색어를 임베딩해 pgvector에서 관련 단위를 찾고, 그 결과를 재료로 글을 씁니다.
  • 작업은 PostgreSQL 큐로 돌립니다. 실패하면 간격을 늘려 다시 시도하고, 멈춘 작업은 되살립니다.

틀렸던 것과 고친 것

  • 4만 자가 넘는 메모에서는 최소 단위가 하나도 나오지 않은 채 작업이 끝나고 있었습니다. 긴 메모를 조각으로 나눠 처리하게 바꾸자, 그 메모 하나(51조각)에서 580개가 나왔습니다.
  • 그 과정에서 임베딩 서버가 긴 입력을 오류 없이 잘라 버린다는 것을 측정으로 확인했습니다. 그래서 입력 길이 상한을 클라이언트에서 직접 둡니다.
  • 한 번에 보내는 임베딩 개수도 재 봤습니다. 처리 시간은 개수에 비례해 늘었고(150개 12.7초, 1,200개 101초), 300개면 이미 요청 시간 한도(30초)에 가까웠습니다. 부하가 걸릴 때를 감안해 150개씩 나눠 차례로 보냅니다.
