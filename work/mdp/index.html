마케팅 데이터 플랫폼 재구축

아모레퍼시픽. 다섯 곳에 흩어져 돌던 파이프라인을 STG → ODS → DW 한 줄 흐름으로

배경

아모레퍼시픽 빅데이터 플랫폼 팀에서 마케팅 데이터 담당을 맡았습니다. 데이터는 원래 STG → ODS → DW → Mart 순서로 쌓이며 단계마다 맞는 가공을 거쳐야 했습니다.

문제

  • 실제로는 규칙 없이 단계가 섞여 있었습니다.
  • 수집과 적재가 다섯 곳에서 따로 돌았습니다(로컬 Mac, AWS EC2, BigQuery, 광고 데이터 플랫폼, AWS Glue).
  • 어떤 데이터가 어떻게 만들어지는지 흐름이 보이지 않아, 오류 원인을 찾는 데 오래 걸렸습니다.
  • 저장소가 중복되고 스냅샷 구조가 잘못돼 데이터가 계속 불어났습니다.

만든 것1단계 재구축 주도, 동료들의 도움을 받음

  • 수집을 공통 모듈로 옮겼습니다.
  • Snowflake 안을 STG → ODS → DW 한 줄로 정리했습니다. 원본은 ODS까지 보존하고, 가공은 DW에서만 합니다.
  • MDP용 Airflow DAG를 직접 개발해 전체 흐름이 한눈에 보이게 했습니다.

남은 문제와 푼 방법2단계, 단독

  • 정돈하고 나니 재적재가 남았습니다. 마케팅 데이터는 사후 수정이 잦아 해당 기간의 데이터를 지우고 다시 넣어야 했고, 두 시스템을 오가는 6단계 수작업이었습니다.
  • 원천이 들어오기 전에 지우거나 설정을 되돌리는 것을 잊으면 데이터가 비거나 다음 날 배치가 틀어졌습니다.
  • 원천 추출을 Airflow 안으로 옮기고 기간을 파라미터로 받게 했습니다. 원천이 비면 하류를 건너뛰는 검증도 넣었습니다.

결과

일 배치

4시간 넘게→10분 안

재적재

6단계→3단계

약 2시간 반→30분

  • 실수가 나던 수동 설정 단계가 없어졌습니다
  • 외주 인력이 맡던 파이프라인 개발·유지보수를 내부로 가져오고, BigQuery·EC2·로컬 서버를 흐름에서 걷어냈습니다.

근거

사내 자료라 공개할 수 없습니다. 구조도는 직접 다시 그렸습니다. 회사 고유 시스템명과 테이블명은 뺐습니다.
